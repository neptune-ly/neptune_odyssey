# Odyssey expression system

The shared system supports two deliberate expressions. They are composition rules using the same foundations, not separate UI kits.

| Decision | Expressive | Composed |
| --- | --- | --- |
| Primary impression | Bright, approachable, energetic | Assured, clear, substantial |
| Canvas | Warm paper; deep ink at night | Warm paper or institutional field; deep ink at night |
| Colour hierarchy | One vivid hero field plus up to two supporting colour groups | One decisive brand field plus one supporting accent |
| English display | Baloo 2 Bold | Hanken Grotesk Bold |
| Arabic display | Beiruti Bold with Arabic-specific metrics | Beiruti Bold with Arabic-specific metrics |
| Functional text and numbers | Shared body, label and numeric styles | The same styles; density adapts to the task |
| Framing | Generous soft rectangles, independent colour pockets | Aligned bands, clear rules, restrained soft rectangles |
| Illustration | Human narratives, surprising object combinations, lively environments | Precise object studies, architecture, mature human/editorial scenes |
| Motion | Short expressive settle and stagger where helpful | Direct transitions, calm reveals and clear state change |

## Colour roles

Use the shared vivid palette for feature fields, illustrated service categories, editorial panels and selected discovery surfaces. A colour field groups meaning; it is not an extra status. Use ink on cyan, mint, lemon and lilac. Full coral uses deep ink #071A2D for normal text (4.80:1); standard ink is only 3.55:1 on coral. Use light text on the ink field. Validate actual text contrast for a tenant colour before using it as a text background.

Keep action and status semantics stable. A coral brand accent must not silently mean error. A mint discovery card must not silently mean success. Financial review, account identity, amount and outcome remain legible regardless of expression.

In dark mode, keep vivid feature fields vivid and frame them with deep ink. Do not globally desaturate every accent into the same blue-grey. Reading surfaces can use quieter dark containers. Illustration may retain its own intentional light or coloured field; do not invert raster art mechanically.

## Shape and composition roles

Use existing radius/space primitives through named roles: compact controls, standard controls, cards, expressive pockets and capsules. A standard action uses a soft rectangle; a badge may use a capsule. State treatments should follow the silhouette rather than acquiring a different arbitrary shape.

Each specimen needs one visual anchor, a clear secondary tier and a quiet working area. Avoid nested cards that do not group a distinct task. Use rules and spacing for ordinary lists. When an institution's brand field is strong, the working area can be simple without making the whole composition bland.

## Illustration variety

Choose a visual category before a subject: human narrative, object study, environment/architecture, or conceptual composition. Change at least the subject category, viewpoint or silhouette between adjacent editorial placements. Do not recolour one composition and call it a new product world. Reuse shared craft, not the same pose.

Use a professional contour, flat colour planes, selective detail and coherent perspective. Expressive work may use a coral spark, lively gesture or layered colour field. Composed work may use a precise crop, architectural rhythm or a carefully observed object. Both should remain visibly related.

## How a designer or agent should work

1. Choose expressive or composed from the audience and task.
2. Choose the dominant field, supporting colour groups and display voice.
3. Compose existing controls, data and navigation components. Establish functional hierarchy before adding editorial content.
4. Brief the image model or illustrator from the story and visual category. Keep shared craft; vary composition.
5. Inspect actual pixels at intended size. Compare with the canonical specimens, then verify Arabic, dark mode and essential interaction states.

The result must look like Odyssey before a product logo is added. If it differs from a generic UI only through a logo and a primary-colour substitution, the expression is unfinished.
